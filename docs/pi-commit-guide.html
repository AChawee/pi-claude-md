pi-commit — มาตรฐาน commit ของทีมpi-commit — the team commit standard

ทุก commit ต้องบอกว่า ใครทำ (git user.name = รหัสพนักงาน 4 หลัก) และ ทำอะไร (type(scope): description) เพื่อให้ระบบ task ของทีมวิเคราะห์งานรายคนและรายโปรเจกต์ได้อัตโนมัติในภายหลัง ถ้า commit ไม่ตรงรูปแบบ hook จะปฏิเสธและบอกว่าต้องแก้อะไร

Every commit says who did it (git user.name = your 4-digit employee code) and what was done (type(scope): description), so the team's task system can later analyse work per person and per project automatically. A hook refuses commits that do not follow the format and tells you what to fix.

  1. ติดตั้ง pluginInstall the plugin /plugin marketplace add ken1lnw/pi-claude-md แล้วthen /plugin install pi-commit@pi-claude-md (ขั้นตอนเต็มอยู่ในหัวข้อติดตั้ง)(full steps in the Install section)
  2. ตั้งรหัสพนักงานSet your employee code /pi-commit:setup แล้วใส่รหัส 4 หลักthen enter your 4-digit code
  3. commit ตามปกติCommit as usual ใช้ git commit, VS Code หรือสั่งUse git commit, VS Code, or run /pi-commit:commit

ภาพรวมการทำงานHow it works

ไม่ว่าจะ commit ทางไหน git จะรัน hook commit-msg ก่อนบันทึกทุกครั้ง hook ตรวจตามลำดับด้านล่าง

Whichever way you commit, git runs the commit-msg hook before saving. The hook checks in the order below.

เลื่อนผังไปทางซ้าย-ขวาเพื่อดูทั้งหมดScroll the chart sideways to see all of it.

อ่านผังเป็นข้อความRead the flowchart as text
  1. แก้โค้ด แล้ว commit ผ่าน Claude Code (/pi-commit:commit), ช่อง Source Control ของ VS Code หรือ git commit ใน terminal
  2. git รัน hook commit-msg
  3. remote ไม่อยู่ใต้ tycthailand หรือไม่ → ไม่ตรวจ commit สำเร็จ
  4. เป็น commit ที่ได้รับยกเว้น (deploy! ล้วน, Merge, Revert, fixup!/squash!/amend!) หรือไม่ → ไม่ตรวจ commit สำเร็จ
  5. user.name เป็นเลข 4 หลักพอดีหรือไม่ → ถ้าไม่ใช่ commit ถูกปฏิเสธ
  6. บรรทัดแรกเป็น type(scope): description ที่ type ถูกต้องและ description ≥ 10 ตัวอักษร ไม่คลุมเครือหรือไม่ → ถ้าไม่ใช่ commit ถูกปฏิเสธ
  7. ถูกปฏิเสธ: อ่าน Problem และ Example แก้ข้อความ แล้ว commit ใหม่ (กลับไปข้อ 1)
  8. ผ่านทั้งหมด: commit สำเร็จ author เป็นรหัสพนักงาน แล้วคุณ push เอง
  1. Change code, then commit via Claude Code (/pi-commit:commit), the VS Code Source Control panel, or git commit in a terminal.
  2. git runs the commit-msg hook.
  3. Is the remote under tycthailand? If not, nothing is checked and the commit is saved.
  4. Is it exempt (only deploy!, Merge, Revert, fixup!/squash!/amend!)? If yes, nothing is checked and the commit is saved.
  5. Is user.name exactly 4 digits? If not, the commit is rejected.
  6. Is the first line type(scope): description with a known type and a description of at least 10 characters that is not vague? If not, the commit is rejected.
  7. Rejected: read Problem and Example, fix the message and commit again (back to step 1).
  8. All passed: the commit is saved with the employee code as author, and you push yourself.

Claude Code ข้าม hook ไม่ได้ — plugin บล็อกคำสั่งที่มี --no-verify, -n หรือแก้ core.hooksPath ถ้าถูกบล็อกให้แก้ข้อความ commit ให้ถูกรูปแบบแล้ว commit ตามปกติ

Claude Code cannot bypass the hook. The plugin blocks commands that use --no-verify, -n or change core.hooksPath. If blocked, fix the commit message and commit normally.

ผังการติดตั้ง (setup)Setup flow

อ่านผังเป็นข้อความRead the flowchart as text
  1. รัน /pi-commit:setup หรือ sh plugins/pi-commit/scripts/setup.sh install
  2. ใส่รหัสพนักงาน 4 หลัก ถ้าไม่ใช่เลข 4 หลักจะถามใหม่
  3. ยืนยัน Apply? [Y/n]
  4. ถ้า core.hooksPath ถูกตั้งโดยเครื่องมืออื่นอยู่แล้ว setup จะหยุด ไม่เปลี่ยนอะไร และบอกวิธีทำต่อ
  5. ไม่เช่นนั้นตั้ง user.name, core.hooksPath (~/.config/pi-claude-md/git-hooks) และ commit.template แล้วเสร็จ
  1. Run /pi-commit:setup or sh plugins/pi-commit/scripts/setup.sh install.
  2. Enter your 4-digit employee code; if it is not exactly 4 digits you are asked again.
  3. Confirm Apply? [Y/n].
  4. If core.hooksPath is already set by another tool, setup stops, changes nothing and tells you how to proceed.
  5. Otherwise it sets user.name, core.hooksPath (~/.config/pi-claude-md/git-hooks) and commit.template, then finishes.

รูปแบบ commitCommit format

บรรทัดแรกของข้อความ commit ต้องเป็น type(scope): description บรรทัดถัดไป (body) จะเขียนหรือไม่ก็ได้

The first line of the commit message must be type(scope): description. A body below it is optional.

feat(kpi): เพิ่มกราฟรายเดือน
type — ประเภทงานthe kind of work
scope — ส่วนของระบบที่แก้ (ไม่ใส่ก็ได้ และถ้าไม่ใส่ให้ตัดวงเล็บออกด้วย)the area changed (optional; leave out the parentheses too if you skip it)
description — ทำอะไรwhat was done

กฎRules

  • type เป็นตัวพิมพ์เล็ก และต้องอยู่ในรายการด้านล่างtype is lowercase and from the list below.
  • scope คือส่วนของระบบที่คุณแก้ เป็นคำภาษาอังกฤษพิมพ์เล็ก 1 คำ เช่น auth, kpi, tasks, api, db, ui ห้ามใช้ชื่อ task, รหัส task หรือชื่อคนscope is the part of the system you changed: one lowercase English word such as auth, kpi, tasks, api, db, ui. Not a task name or ID, and not a person.
  • หลังเครื่องหมาย : เว้นวรรค 1 ช่องพอดีExactly one space after the :.
  • description เป็นภาษาไทยหรืออังกฤษก็ได้ ยาวอย่างน้อย 10 ตัวอักษร และบอกว่าเปลี่ยนอะไร ไม่ใช่ "update code" หรือ "minor changes"description is Thai or English, at least 10 characters, and says what changed, not "update code" or "minor changes".

รายการ typeTypes

typeใช้เมื่อUse for
featเพิ่มความสามารถใหม่new feature
fixแก้บั๊กbug fix
perfทำให้เร็วขึ้นperformance
refactorปรับโครงโค้ด พฤติกรรมเหมือนเดิมrestructure, same behavior
docsเอกสารdocumentation
testเทสtests
styleจัด format ไม่เปลี่ยน logicformatting only
builddependency, Dockerfile, การ builddeps, Docker, build
ciGitHub Actionspipeline
choreงานดูแลทั่วไปmaintenance
securityแก้ช่องโหว่vulnerability fix
revertย้อน commitundo a commit
etcงานที่ไม่เข้าหมวดไหนanything else

When a commit passes, the hook appends Emp: <code> to the message for you — nothing to type. If it is already there (e.g. on --amend) the value is replaced, never duplicated. This line lets anyone viewing the commit on github.com see the code too, because the GitHub web page shows the GitHub account, not user.name.

บนเว็บ GitHub เห็นชื่ออะไรWhich name shows on github.com?

หน้าเว็บ GitHub แสดง บัญชี GitHub ของคนที่ commit (จับคู่จาก email) ไม่ใช่ user.name รหัสพนักงานจึงเห็นได้จากบรรทัด Emp: ใต้ข้อความ commit ส่วน git log, VS Code และ GitHub API (commit.author.name) แสดงรหัสเป็น author ตรง ๆ

github.com shows the committer's GitHub account (matched by email), not user.name, so the code is visible through the Emp: line under the message. git log, VS Code and the GitHub API (commit.author.name) show the code as the author directly.

The repo is not under tycthailand, or setup has not been run on that machine. Check with:

sh plugins/pi-commit/scripts/setup.sh status
setup บอกว่า core.hooksPath is already setSetup says core.hooksPath is already set

เครื่องมืออื่นใช้ global hooks อยู่ setup ไม่ได้เปลี่ยนอะไรเลย คุณต้องตัดสินใจเองว่าจะรันคำสั่งนี้แล้วทำ setup ใหม่หรือไม่

Another tool owns the global hooks and setup changed nothing. You decide whether to run this and then run setup again.

git config --global --unset core.hooksPath

No, because no hook runs there. Still write them in the same format.

No. Only the global user.name, core.hooksPath and commit.template.

อัปเดต pluginUpdating the plugin

ใน Claude Code เปิด /plugin ไปที่ Marketplaces เลือก pi-claude-md แล้วอัปเดต (หรือเปิด auto-update) จากนั้นรัน /pi-commit:setup อีกครั้งเพื่อคัดลอก hook ตัวใหม่

In Claude Code open /plugin, go to Marketplaces, pick pi-claude-md and update (or enable auto-update). Then run /pi-commit:setup again to copy the new hook.
